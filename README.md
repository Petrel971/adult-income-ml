# Adult income classifier: from raw census data to a served prediction

Group project for *Applied ML: Foundations, Engineering & Evaluation* (Ilana Sebag, Albert School, MSc 1).
**Group 1**: Lucas Petrelluzzi, Manuel Andrade, Amine Ennadzim, Grégoire Mismaque.

**Dataset: Adult / Census Income** (`fetch_openml(name="adult", version=2)`), 48,842 people from the
1994 US census. Binary target: does the person earn more than 50K dollars a year (24% yes)?
Sensitive attribute used for the fairness audit: `sex`.

The written report is in `report/report.pdf`. This README only explains how to run the code.

## Results in one table (untouched test set, 9,758 people)

| Model | PR-AUC | ROC-AUC | F1 | Precision | Recall | Brier |
|---|---|---|---|---|---|---|
| No-skill baseline | 0.239 | 0.500 | 0.000 | 0.000 | 0.000 | 0.182 |
| Logistic regression (tuned) | 0.769 | 0.907 | 0.689 | 0.649 | 0.733 | 0.102 |
| Random forest (tuned) | 0.802 | 0.916 | 0.700 | 0.651 | 0.758 | 0.095 |
| **Gradient boosting (tuned, final)** | **0.819** | **0.926** | **0.720** | 0.704 | 0.736 | **0.090** |

Decision thresholds are chosen on the validation set (0.36, 0.35, 0.41). Final model: ECE 0.007
(well calibrated). Fairness on `sex`: the true-positive-rate gap goes from 0.106 to 0.013 with
group thresholds, for 0.007 of F1.

## Reproduce

Python 3.12. The dataset is downloaded from OpenML on first run and cached in `data/`.

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt   # exact versions are pinned
python main.py                 # all stages (about 25 minutes on a laptop, tuning included)
pytest                         # checks
```

Run a single stage with `python main.py eda`, `python main.py tune`, etc.
Stages, in order: `eda`, `baselines`, `tune`, `compare`, `explain`, `calibrate`, `fairness`.
Everything is seeded (`seed: 42` in `config.yaml`).

Shortcuts: `make install`, `make test`, `make all`, `make summary`, `make serve`.

## Serve a prediction

```bash
uvicorn src.serve:app --port 8000
curl -X POST localhost:8000/predict -H "Content-Type: application/json" -d @examples/person.json
```

Several records at once: `POST /predict/batch` with a JSON list of records.

Response of `/predict`:

```json
{"probability": 0.8026, "prediction": 1, "label": ">50K", "threshold": 0.4093, "model": "hist_gb"}
```

The endpoint takes a raw record (missing values allowed), runs the whole fitted Pipeline
(feature engineering, preprocessing, model) and returns the probability and the decision at the
threshold chosen on the validation set. Interactive documentation: `http://localhost:8000/docs`.

## Data dictionary

| Column | Type | Note |
|---|---|---|
| age | int | 17 to 90 |
| workclass | category | missing for most people without a job |
| education-num | int | 1 to 16; `education` is the same information as text, dropped |
| marital-status, relationship | category | strongly linked to each other and to sex |
| occupation | category | missing together with workclass |
| race, sex | category | sex is the sensitive attribute of the fairness audit |
| capital-gain, capital-loss | float | zero for most people, log-transformed in the features |
| hours-per-week | int | 1 to 99 |
| native-country | category | 41 levels, rare ones grouped (`min_frequency=20`) |
| fnlwgt | float | census sampling weight, dropped (describes the survey, not the person) |

Target: `income_gt_50k` = 1 if income > 50K (23.9% of the 48,790 records).

## Metrics and decision threshold

- **PR-AUC** (average precision) is the main metric: with 24% positives, "always no" already
  has 76% accuracy, and ROC-AUC is flattered by the many negatives. The no-skill PR-AUC is 0.24.
- The models are trained on the true class proportions. The decision threshold (0.41) is chosen
  on the validation set to maximise F1; with real business costs, minimise the expected cost instead.
- Moving the threshold changes precision and recall, never PR-AUC or ROC-AUC
  (`tests/test_evaluate.py`).

## Tuning budget

| Model | Trials | Best 5-fold CV PR-AUC | Fit time |
|---|---|---|---|
| Logistic regression | 30 | 0.784 ± 0.007 | 1.4 min |
| Random forest | 30 | 0.817 ± 0.005 | 2.7 min |
| Gradient boosting | 50 | 0.832 ± 0.006 | 4.1 min |

Regenerate this table with `python -m src.runlog_summary` (writes
`reports/tables/run_log_summary.csv`). The best inner score of gradient boosting is optimistic:
nested CV gives 0.828 ± 0.005.

## Data discipline

| Set | Size | Used for |
|---|---|---|
| Train (60%) | 29,274 | fitting, cross-validation, Optuna tuning |
| Validation (20%) | 9,758 | model comparison, thresholds, calibrators, fairness thresholds |
| Test (20%) | 9,758 | final numbers only, computed once |

All preprocessing lives inside one scikit-learn `Pipeline`, so it is re-fitted in every CV fold.
